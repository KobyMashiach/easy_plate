#### P2-7. 04:14 — a household listener that died on an error was neither followed nor re-read for the rest of the session
- Files: `lib/core/sync/user_cloud_collection.dart` (`CloudMirror.isListening`; `listen` onError), `lib/core/sync/cloud_sync_service.dart` (`refresh`); test fakes in `test/core/sync/cloud_sync_service_test.dart`, `test/core/services/auth_session_service_test.dart`.
- Problem: in a household, the resume `refresh` skips every shared mirror while `_listening` is true, because the listeners follow them live. But a listener Firestore closed on an error (a transient permission/rules error, a backend reset) kept its dead `_subscription` and `_listening` stayed true, so that collection (recipes, plans, lists…) stopped receiving the other members' changes *and* was skipped by every resume pass until a rehome or relaunch.
- Fix: the mirror marks itself not listening on error (`isListening`); `refresh` skips only shared mirrors that are actually listening, hydrates a dead one like an own mirror (the hydrate is what reconciles deletions made during the gap), then reopens its listener (only while still listening for the same account).
